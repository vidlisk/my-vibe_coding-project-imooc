## 1. 背景与问题

### 1.1 背景

多数人有"钱不知不觉花光"的困扰：记不住每一笔小支出，月底无法说清钱花在哪。现有记账工具要么功能复杂（专业财务软件），要么广告多、体验差、强迫绑定。家庭/情侣需要**共同记账**，小微企业和个体户需要**收支清晰、能出报表**，但市面产品往往只服务单一角色。

### 1.2 核心问题

1. **记账太麻烦**：录入路径长，记一笔要 30 秒以上，用户容易放弃。
2. **坚持不下来**：缺少正向反馈（图表、总结），记几天就断更。
3. **只有记录没有洞察**："这个月外卖花了多少""比上月多花在哪"无法快速回答。
4. **多人场景缺失**：情侣/家庭想共用一本账，小微/个体户想分清楚经营收支，却没有合适的轻量工具。

### 1.3 产品机会

做一款**极简、快、多人可共享**的财务记账工具：**3 秒记一笔，一眼看明白，一本账一起记**。V1 以 Web 网页形态先跑通核心价值，后续以同一账号体系扩展 App 与小程序。

## 2. 产品定位与目标

### 2.1 一句话定位

> 一款打开即记、自动分类、图表直观、可多人共享的极简记账工具。

### 2.2 产品目标

| 目标      | 衡量方式        | 目标值（V1 上线 3 个月） |
| ------- | ----------- | --------------- |
| 让记账成为习惯 | 记账留存率（D30）  | ≥ 30%           |
| 单笔录入足够快 | 单笔记账平均耗时    | ≤ 5 秒           |
| 用户能看到价值 | 周活跃中查看统计占比  | ≥ 60%           |
| 覆盖多人场景  | 开通共享账本的用户占比 | ≥ 15%           |

### 2.3 非目标（V1 明确不做）

- ❌ 不做投资理财、股票基金跟踪
- ❌ 不做发票扫描报销、税务申报
- ❌ 不做银行/支付宝自动同步流水（涉及三方接口，留到后续）
- ❌ 不做社区/内容/广告
- ❌ V1 不做原生 App 与小程序（仅规划，不实现）

## 3. 用户画像与使用场景

### 3.1 目标用户分层

**① 个人用户（核心）**：18-45 岁上班族/学生，日常消费高频小额（外卖、咖啡、交通、网购），想清楚钱花在哪、攒下钱。

**② 家庭/情侣用户（重要）**：共同生活的伴侣或家庭，希望共用一本账记录共同开销，成员各自也能记自己的账。

**③ 小微/个体户用户（延展）**：个体户、夫妻店、自由职业者，需要同时记**经营收支**和**个人收支**，月底能导出简单报表算盈亏。

### 3.2 核心使用场景

| 场景     | 描述                      | 关键诉求           |
| ------ | ----------------------- | -------------- |
| 随手记一笔  | 吃完午饭/买完东西，掏出手机在浏览器里记下这笔 | 快、不用想分类、自动填时间  |
| 月底复盘   | 月底想看这个月花了多少、花在哪、比上月如何   | 图表直观、能对比上月     |
| 预算控制   | 设每月预算，快超支时被提醒           | 预算进度可视化、超额提醒   |
| 查一笔旧账  | 回忆某天某笔花了多少              | 搜索、按分类/时间/成员筛选 |
| 情侣共同记账 | 两人记在同一本账上，都能看到、都能记      | 账本共享、成员权限      |
| 个体户算盈亏 | 把进货、销售、房租等经营收支记下来，月底看利润 | 经营分类、收支报表、导出   |

## 5. 功能需求详述

### 5.1 账号体系（P0）

**背景**：Web 网页端数据无法仅靠浏览器本地可靠保存（清除数据即丢失），且后续共享账本、多设备、App/小程序都依赖账号。因此 V1 采用**账号 + 云存储**方案。

**功能**：

- 手机号 + 短信验证码登录，首次即自动注册。
- 登录态持久化（如 30 天免登录），无需每次记账都登录。
- 提供"退出登录""账号注销"入口；注销需二次确认并告知数据删除后果。
- 预留第三方登录（微信扫码/小程序登录）接口，V2/V3 复用。

**验收标准**：

- 新用户从注册到开始记账 ≤ 1 分钟。
- 多设备登录同一账号，数据一致。
- 密码/验证码错误有明确提示，验证码 60 秒防刷。

---

### 5.2 账本与成员（P0 单账本 / P1 共享）

**目标**：既支持个人，也支持家庭/情侣、小微/个体户的多成员协作。

**概念**：

- **账本（Ledger）**：一个独立的数据容器，包含自己的分类、流水、预算、成员。
- 新用户注册后自动创建一个"我的账本"（个人使用）。
- 用户可创建多个账本（如"家庭账本""店里账本"），切换使用。

**共享账本（P1）**：

- 账本创建者（管理员）通过邀请链接/邀请码邀请成员。
- 成员角色：**管理员**（管理成员、删账本）、**成员**（记账、看账）。
- 每笔流水记录**归属成员**，列表和统计可按成员筛选。

**验收标准**：

- 个人用户无需任何配置即可记账。
- 账本成员可同时记账，数据实时同步，权限正确隔离。
- 数据模型预留多账本/多成员字段，避免后续重构（见第 8 章）。

---

### 5.3 快速记账（P0，核心）

**目标**：从打开到完成一笔记录 ≤ 5 秒。

**页面**：首页即记账页（打开即输入金额），无需点击"新增"。

**字段**：

| 字段  | 说明          | 默认值      | 是否必填            |
| --- | ----------- | -------- | --------------- |
| 金额  | 数字键盘输入，支持小数 | 空        | 是               |
| 类型  | 支出 / 收入     | 支出       | 是               |
| 分类  | 从分类库选择      | 最近一次使用分类 | 是               |
| 时间  | 记账时间，可回填    | 当前时间     | 是               |
| 备注  | 自由文本，选填     | 空        | 否               |
| 账本  | 所属账本        | 当前账本     | 是（默认隐藏）         |
| 成员  | 归属成员        | 当前登录用户   | 是（默认隐藏，多人账本时展示） |

**交互细节**：

- 打开自动聚焦金额输入框，弹出数字键盘。
- 输入金额后点分类即完成保存（分类即"保存"按钮）。
- 最近使用分类置顶；键盘区提供"支出/收入"切换。
- 记账成功轻量反馈（震动/短暂 toast），不打断连续记账。

**验收标准**：

- 熟练用户单笔记账 ≤ 5 秒、≤ 4 次点击。
- 冷启动（首次加载）≤ 2 秒，二次访问秒开（配合缓存）。

---

### 5.4 分类管理（P0，双轨）

**目标**：个人和经营两类场景都能"开箱即用"。

**默认分类库**：

**支出（个人）**：餐饮、交通、购物、居住、娱乐、医疗、学习、人情、其他。

**收入（个人）**：工资、奖金、理财、兼职、其他。

**经营收支（小微/个体户）**：

- 经营收入：销售收入、服务收入、其他经营收入。
- 经营支出：进货成本、房租/摊位费、员工工资、水电、税费、物流、设备、其他经营支出。

**功能**：

- 用户可新增/重命名/删除自定义分类，并选择图标与颜色。
- 分类支持排序，常用分类固定置顶。
- 删除分类需二次确认：该分类下已有流水将迁移至"其他"或需先处理。

**验收标准**：

- 首次使用无需配置即可记账。
- 个体户用户可完整区分经营与个人收支，不互相混淆。

---

### 5.5 账单流水（P0）

**目标**：以最自然的方式浏览历史账单。

**页面结构**：

- 按**天分组**，组头显示日期 + 当日合计（支出/收入）。
- 每条流水展示：分类图标、备注（无备注显示分类名）、金额（支出红色、收入绿色）、成员标识（多人账本时）。
- 顶部月份切换器（左右滑动/下拉选择）。

**操作**：

- 点击某条 → 编辑页（改金额、分类、时间、备注、删除）。
- 长按某条 → "复制一笔 / 删除"快捷菜单。

**验收标准**：

- 1000 条流水列表滚动流畅（列表虚拟化）。
- 按天/月/成员汇总金额准确。

---

### 5.6 统计分析（P0/P1）

**目标**：回答"钱花哪了、趋势如何"。

- **P0 月度总览卡片**：本月支出/收入/结余，环比上月增减。
- **P0 分类占比环形图**：点击扇区查看分类总额与笔数。
- **P1 月度趋势折线图**：近 6/12 个月支出与收入趋势。
- **P1 分类明细钻取**：进入分类明细，可进一步按天/按成员查看。
- **P1 每日支出柱状图**：本月每日支出分布。

**验收标准**：

- 图表数据与流水明细严格一致（对账）。
- 环形图占比精确到小数点后一位，总和为 100%。

---

### 5.7 报表导出（P1，小微/个体户刚需）

**目标**：让个体户/小微月底能拿到可用的收支报表。

**功能**：

- 导出 **CSV**（Excel 可读）与 **简易收支报表**（月度收入/支出/结余按分类汇总）。
- 可选时间范围与账本范围。
- 报表可导出为 PDF 或打印（P1 可选）。

**验收标准**：

- CSV 字段完整：日期、类型、分类、金额、成员、备注。
- 报表数据与流水一致，月度结余计算正确。

---

### 5.8 预算管理（P1）

**目标**：帮助用户控制开销。

**功能**：

- 设置月度总预算，可选分类预算（如"餐饮 ≤ 1500"）。
- 统计页/首页展示预算进度条：超 80% 变黄、超 100% 变红。
- 超过总预算/分类预算时发送提醒。

**验收标准**：

- 预算进度与流水实时联动。
- 超额提醒可关闭或调阈值。

---

### 5.9 数据存储与安全（P0）

**方案**：

- **云端存储**：数据加密存储于服务端（传输 HTTPS + 存储加密）。
- **多设备同步**：同账号多设备实时一致。
- **隐私承诺**：仅存储记账数据，不采集、不售卖；支持导出与注销删除。
- **数据可迁移**：支持导出 CSV 与完整备份，用户可随时带走。

**验收标准**：

- 断网时页面可用（已加载数据），恢复网络后自动同步。
- 注销账号后数据按规定删除。

## 7. 关键交互流程

### 7.1 主流程：记一笔支出

```
打开 Web → 已登录则直接进入记账页，未登录引导手机号登录
  → 自动聚焦金额输入框，弹出数字键盘
  → 输入金额 "28.5"
  → 点击分类 "餐饮-午餐"（或最近使用分类）
  → 保存成功，页面复位，可继续记下一笔
```

### 7.2 主流程：创建共享账本并邀请成员

```
我的 → 账本管理 → 新建账本 → 命名（如"我们的家"）
  → 生成邀请链接/邀请码 → 发送给伴侣
  → 对方登录后输入邀请码加入 → 成为成员，可共同记账
```

### 7.3 异常流程

- 金额为空 → 分类/保存按钮置灰，提示"请输入金额"。
- 金额异常（超 9 位）→ 输入层限制并提示。
- 未登录/登录过期 → 引导登录，登录后回到原页面。

## 8. 数据需求

### 8.1 核心数据实体

**用户（User）**：id、手机号、昵称、头像、创建时间、状态。

**账本（Ledger）**：id、名称、类型（personal/family/business）、创建者、创建时间。

**成员（Member）**：账本 id、用户 id、角色（admin/member）、加入时间。

**流水（Transaction）**

| 字段                      | 类型       | 说明               |
| ----------------------- | -------- | ---------------- |
| id                      | string   | 主键               |
| ledger_id               | string   | 所属账本             |
| member_id               | string   | 归属成员             |
| type                    | enum     | expense / income |
| amount                  | decimal  | 金额，正数            |
| category_id             | string   | 关联分类             |
| occurred_at             | datetime | 记账时间             |
| note                    | string   | 备注，可空            |
| created_at / updated_at | datetime | 创建/更新时间          |

**分类（Category）**

| 字段           | 类型     | 说明                  |
| ------------ | ------ | ------------------- |
| id           | string | 主键                  |
| ledger_id    | string | 所属账本（或个人默认）         |
| name         | string | 名称                  |
| type         | enum   | expense / income    |
| scope        | enum   | personal / business |
| icon / color | string | 图标/颜色               |
| is_system    | bool   | 是否系统默认              |
| sort_order   | int    | 排序                  |

**预算（Budget）**：id、ledger_id、category_id（null 为总预算）、month、amount。

> 说明：V1 即引入 `ledger_id`、`member_id`、`scope` 字段，为家庭/情侣共享、小微/个体户经营核算预留结构，避免后续重构。

## 10. 埋点与数据指标

> 注：埋点仅统计使用行为，**不采集记账内容**。

| 指标          | 定义               | 用途       |
| ----------- | ---------------- | -------- |
| 单笔记账耗时      | 从打开到保存成功时间       | 衡量录入效率   |
| 记账完成率       | 进入记账页且成功保存比例     | 衡量流程漏斗   |
| D7 / D30 留存 | 新用户第 7/30 天仍记账比例 | 衡量习惯养成   |
| 人均记账笔数/天    | 日均记账条数           | 衡量活跃度    |
| 共享账本开通率     | 开通共享账本的用户占比      | 衡量多人场景价值 |
| 统计/报表访问率    | 周活跃中查看统计或导出占比    | 衡量洞察价值   |

## 12. 风险与依赖

| 风险         | 影响       | 应对                  |
| ---------- | -------- | ------------------- |
| 记账习惯难以坚持   | 留存低      | 强化反馈（成就/提醒/月度总结）    |
| 默认分类不符用户习惯 | 记账效率下降   | 双轨分类 + 自定义 + 后续智能分类 |
| 账号登录增加使用门槛 | 首次转化低    | 手机号一键登录，注册即用，游客可先体验 |
| 共享账本数据权限出错 | 信任受损     | 明确角色权限 + 操作日志（后续）   |
| 功能蔓延       | V1 迟迟不上线 | 严格按 P0 裁剪，砍掉非核心     |

## 13. 待确认问题（Open Questions）

1. **登录方式**：V1 是否接受"手机号 + 短信验证码"作为唯一登录方式？是否需要邮箱登录？
2. **账本数量**：免费用户可创建账本/成员数量上限（如免费 3 账本、每账本 5 人）？是否收费？
3. **个体户报表**：V1 是否需要导出 PDF 报表，还是 CSV 即可满足？
4. **共享账本权限**：是否需要"只读成员"角色，还是仅"管理员/成员"两种？
5. **数据留存**：注销后数据是立即删除还是保留 7 天可恢复？
